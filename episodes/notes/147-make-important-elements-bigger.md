# 147 · Make Important Elements Bigger

**Category:** UI · [Video](https://www.youtube.com/watch?v=va8wt2yGviY) · [Transcript](../transcripts/147-make-important-elements-bigger.md)

## In one sentence
Size menu items by importance, with the most-used modes as the biggest icons, so players reach what matters fastest, and watch for the costs to versatility and translation.

## Key ideas
- Most games list menu items from top to bottom, which makes sense. Starting with Meteos, Sakurai began presenting his menus as icons, usually of varying size.
- Size signals priority: bigger icons are the ones used more often, and smaller ones are rarely used. "It's all about ease of access."
- The GameCube controller was likely designed on the same idea: a big A button and small X and Y buttons, so you not only see but also feel which button to press.
- It isn't the best fit for every game. Each button's importance varies from game to game, so in a game where all buttons have equal value, a weighted layout can be harder to use (e.g., when the face buttons are used to navigate menus). Changing the weight of each option can cost you versatility.
- Icon menus have caused headaches in translation. Languages that take up more horizontal space are hard to fit. The layout works great for Japanese, and Sakurai apologizes if it didn't come across as well in other countries.
- A simple list is fine. Sizing by importance is another method, for when you want to give some elements more weight.

## Do this
- Rank your menu options by how often players will use them, and make the most-used ones the largest tiles or icons, shrinking the rarely used ones.
- When one action clearly dominates a game, make its button the biggest or most prominent so players can find it by feel. Keep buttons equal when the game uses them equally.
- Mock up icon and tile labels in your longest target language early, since languages that take more horizontal space are hard to fit into icon menus.

## Avoid
- Giving buttons or menu items unequal weight when all of them matter equally. It makes controls harder to use and costs versatility.
- Designing icon labels for one language only and leaving translation to fit afterward.

## Examples from the episode
- **Meteos onward:** menus presented as icons of varying size.
- **Smash Bros. menu:** a layout unique to Smash, with bigger icons for more-used modes. Translations that take more horizontal space were hard to fit.
- **GameCube controller:** a big A button and small X and Y buttons, so you feel which one to press.

## Quote
> The size indicates which modes take priority and what's important. (00:28)
