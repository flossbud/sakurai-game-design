# 104 · Don't Be Unresponsive

**Category:** Planning & Game Design · [Video](https://www.youtube.com/watch?v=eia2IAmvtKI) · [Transcript](../transcripts/104-dont-be-unresponsive.md)

## In one sentence
Make sure every button press gets some reaction: map confirm to several buttons, double up functions, and let presses during cutscenes bring up a skip prompt, because players press buttons when they want something from the game.

## Key ideas
- Consoles have almost a dozen plain press buttons. In menus and other UI, more than one button should work as confirm.
- Even simple action games with only one or two functions can put the same function on several buttons. Redundant is better than a button that does nothing. That doesn't mean every last button needs a function.
- Play is a two-way flow: information goes from your hands to the computer and back to your eyes and ears. The hand-side signal is vital, and everyone plays their own way, so when a player presses a button they should get feedback. An action with no reaction feels lacking.
- If L also works as confirm or action, players can play one-handed. Having to feel around for which button does what is a downside, but it still beats unresponsive controls.
- Cutscenes especially should react to button presses, for example with a prompt to skip. Players press buttons because they want something from the game.
- Avoid ambiguous responses that don't make it clear whether the button registered.
- No response isn't always bad, but games are about actions and reactions. (Aside: the "1-2" sticker on his controller means controller 2 for Switch number 1. He has five or six at home.)

## Do this
- In menus, accept confirm from several buttons (e.g., the main confirm button plus a shoulder button like L) so any natural press works and one-handed play is possible.
- In games with only one or two actions, assign each action to multiple buttons instead of leaving most buttons dead.
- During cutscenes, respond to any button press, for example by showing a skip prompt.
- Give every accepted press a clear, unambiguous signal (sound, highlight, animation) so players know it registered.
- For each game state (menus, gameplay, cutscenes), go through the controller map and list which buttons currently do nothing. Give them a sensible reaction unless silence is deliberate.

## Avoid
- Buttons that produce no reaction at all.
- Ambiguous feedback that leaves players unsure whether their press registered.

## Examples from the episode
- **Menus on a console controller:** using L as an extra confirm/action button allows one-handed play.
- **Cutscenes:** a button press should at least show a prompt to skip.
